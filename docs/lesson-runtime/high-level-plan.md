# Lesson Runtime — High-Level Plan (product/architecture brief)

> Уровень фиксации решения до имплементации: что строим, зачем, какой контракт доказываем, где границы.
> Джун-план (как конкретно реализовать): `junior-plan.md`.

## Ценность: зачем это

**Урок — это данные, а не код.** Педагогика (что и когда показывать ученику) — свойство системы, а не художника. Следствия:

- уроки создаются без разработчика (автор/AI пишет данные);
- уроки хранятся в Git, валидируются, сравниваются;
- качество методики измеримо: один рантайм — много уроков.

Architectural thesis: **new lesson = new data, not new code.**

## Actors

1. **Автор урока** (педагог/AI) — пишет Lesson Definition: objective, prior knowledge, эпизоды (задача → ожидаемый прогноз → reveal → reasoning → check). Не пишет код компонентов.
2. **Ученик** (middle-разработчик) — проходит урок: видит задачу, даёт прогноз, доска раскрывает противоречие, объяснение, проверка. Ученик — участник построения модели, не зритель.
3. **Система** (Lesson Runtime) — исполняет педагогическую механику: гарантирует порядок фаз, проектирует learner projection (`?`-слоты, скрытые ноды), управляет состоянием.

## Behavioral contract

```
task → prediction → reveal → reasoning → check → следующая проблема
```

**Инвариант (тестируемый):** ответ не показывается раньше попытки ученика. Reveal невозможен до prediction — enforce на уровне runtime, не UI.

## Architectural Invariants

**Runtime не содержит знания конкретного урока.**

Runtime может знать (обобщённые сущности):

- `task`, `prediction`, `reveal`, `reasoning`, `check`
- фазы (`prior / task / prediction / reveal / reasoning / update / check`)
- проекция (visible / hidden / `?`-слоты)
- переходы между фазами

Runtime НЕ может содержать:

- `if lesson === "payment"`
- `if concept === "pending"`
- `if lesson === "rate-limiter"`

Здесь проходит граница между **Lesson Definition** (данные, содержит предметное знание) и **Lesson Runtime** (механика, предметно-агностична). Нарушение инварианта = архитектурная ошибка: урок «протёк» в движок.

## RED-GREEN доказательство

Критерий готовности: **второй урок (rate limiter) создаётся БЕЗ изменения runtime** — только новые данные. Это проверяет главный тезис: new lesson ≠ new code.

Stretch criterion (необязательный, если renderer один): один и тот же Lesson Definition исполняется без изменения runtime в двух разных визуальных представлениях.

## Критерии готовности

- [ ] Платёжный урок проходит полный цикл «задача → прогноз → reveal → reasoning → check»
- [ ] Второй урок (rate limiter) создаётся без изменения runtime — только данные (RED-GREEN)
- [ ] Урок можно сгенерировать AI-агентом как данные, и он корректно исполняется
- [ ] Педагогический гейт работает системно: нарушить порядок фаз невозможно из UI
- [ ] (stretch) Один Definition исполняется в двух визуальных представлениях без изменения runtime

## Boundaries (вне этого инкремента)

- визуальные стили / темы
- animation / motion
- редактор уроков (authoring UI)
- learner metrics / аналитика прохождения
- серверная часть, persistence, auth
